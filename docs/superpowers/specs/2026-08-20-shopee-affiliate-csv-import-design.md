# Shopee Affiliate CSV Import Design

**Date:** 2026-08-20
**Branch:** `feat/shopee-affiliate-csv-import`
**Base:** `main`

## 1. Goal

Import the CSV files generated by Shopee Affiliate's official **Lấy link hàng loạt** flow directly into ACP Product Pool.

The CSV is the source of the already-created Shopee affiliate URL. ACP must **not regenerate or wrap** that URL during this flow.

Primary operator flow:

```text
Shopee Affiliate
  → Hoa hồng Sản phẩm
  → select up to 100 products
  → Lấy link hàng loạt
  → Shopee downloads CSV
  → ACP /sanpham/shopee-import
  → upload one or more CSV files
  → parse + preview
  → operator confirms Import
  → Product Pool upsert
```

This phase ends at Product Pool. It does not automatically create posts, approve posts, schedule, or publish.

## 2. Verified CSV contract

The real Shopee CSV supplied for this design contains these columns:

```text
Mã sản phẩm
Tên sản phẩm
Giá
Doanh thu
Tên cửa hàng
Tỉ lệ hoa hồng
Hoa hồng
Link sản phẩm
Link ưu đãi
```

`Link ưu đãi` is an already-created Shopee Affiliate short URL such as:

```text
https://s.shopee.vn/...
```

`Link sản phẩm` is a direct Shopee product URL that exposes canonical `shop_id` and `item_id`, for example:

```text
https://shopee.vn/product/<shop_id>/<item_id>
```

The CSV field labelled `Doanh thu` is visibly populated with values such as `10k+`, `20k+`, `300k+`, matching the sold-count presentation from the Affiliate product page. For this importer it is treated as a **sold-count-like quantity**, not monetary revenue.

## 3. Scope

### In scope

- New workspace: `GET /sanpham/shopee-import`.
- Multi-file CSV upload in one operator action.
- Parse Shopee Affiliate CSV entirely server-side.
- UTF-8/UTF-8 BOM support.
- Column contract validation.
- Row-level validation and errors.
- Preview before DB mutation.
- Idempotent Product upsert.
- Preserve official Shopee affiliate short link as `product.affiliate_url`.
- Set affiliate link state to `READY` for valid imported affiliate links.
- Update existing canonical Shopee Products instead of creating duplicates.
- Import/update price, shop, commission, sold-count and product URL.
- Summaries for `NEW`, `UPDATED`, `UNCHANGED`, `DUPLICATE_IN_UPLOAD`, `ERROR`.
- Focused unit/web tests using in-memory/temp SQLite and synthetic CSV fixtures.
- Operator documentation.

### Out of scope

- Watching `~/Downloads` automatically.
- Browser filesystem access.
- Shopee login automation.
- Reading cookies/session/localStorage.
- Open API access.
- Product Feed access.
- CAPTCHA or anti-bot bypass.
- Private Shopee API reverse engineering.
- Regenerating the Affiliate URL from `SHOPEE_AFFILIATE_ID`.
- Wrapping Shopee Direct URLs with ACCESSTRADE.
- Automatic post creation.
- Automatic review approval.
- Automatic publish.

Automatic Downloads-folder ingestion can be designed as a later phase after this importer is stable.

## 4. Existing ACP model reuse

No parallel Product table is introduced.

Use the existing `product` row and existing catalog fields, including where present:

```text
external_product_id
name
current_price
commission_value
commission_rate
shop_name
units_sold
affiliate_url
affiliate_short_url
affiliate_link_status
affiliate_link_error
affiliate_link_created_at
product_url
first_seen_at
last_seen_at
last_synced_at
updated_at
```

Canonical Shopee identity remains the product identity derived from the direct product URL:

```text
shop_id + item_id
```

The CSV importer is a metadata/affiliate-link ingestion source, not a second product namespace.

## 5. Normalized row model

Introduce a focused parser model, conceptually:

```python
ShopeeAffiliateCsvRow(
    item_id: str,
    shop_id: str,
    name: str,
    current_price: int,
    sold_count: int | None,
    shop_name: str | None,
    commission_rate_percent: float | None,
    commission_amount: int | None,
    product_url: str,
    affiliate_url: str,
    source_filename: str,
    source_row_number: int,
)
```

The parser is pure and has no DB side effects.

## 6. Field mapping

```text
CSV Mã sản phẩm
  → external_product_id / item_id

CSV Tên sản phẩm
  → name

CSV Giá
  → current_price

CSV Tên cửa hàng
  → shop_name

CSV Tỉ lệ hoa hồng
  → commission_rate_percent
  → commission_rate where existing code expects decimal/percent semantics must be preserved explicitly

CSV Hoa hồng
  → commission_amount
  → commission_value when ACP currently uses this field for scoring/display

CSV Link sản phẩm
  → canonical product_url
  → derive shop_id + item_id

CSV Link ưu đãi
  → affiliate_url
  → affiliate_short_url may also point to the same Shopee short URL if existing UI expects a short-link field
  → affiliate_link_status = READY

CSV Doanh thu
  → units_sold (parsed sold-count-like value)
```

The importer must not invent unavailable values such as rating, review count, original price, image URL or category.

Existing richer Product fields that are absent from this CSV must be preserved on update.

## 7. Parsing rules

### 7.1 Price

Support real Shopee Vietnamese display formats observed in the supplied CSV:

```text
53,9k     → 53_900
300,0k    → 300_000
1,2tr     → 1_200_000
2,2tr     → 2_200_000
100,0tr   → 100_000_000
```

Rules:

- trim whitespace;
- decimal comma is allowed;
- `k` means thousand;
- `tr` means million;
- result must be positive integer VND;
- malformed, zero or negative price is a row error.

### 7.2 Commission percent

```text
5%      → 5.0
42,5%   → 42.5
4,51%   → 4.51
```

Reject negative or implausible percentages rather than silently coercing them.

### 7.3 Commission amount

```text
₫2.695       → 2_695
₫126.000     → 126_000
₫4.000.000   → 4_000_000
```

Remove currency marker and Vietnamese thousands separators before integer conversion.

### 7.4 Sold-count-like field

```text
0      → 0
28     → 28
1k+    → 1_000
10k+   → 10_000
20k+   → 20_000
300k+  → 300_000
```

This value is approximate when `+` is present. ACP stores the numeric floor only; it must not present it as exact revenue.

### 7.5 Product URL

Accept only direct HTTPS Shopee Vietnam product URLs supported by the existing canonicalizer.

Derive both `shop_id` and `item_id` from the URL and require:

```text
CSV Mã sản phẩm == derived item_id
```

A mismatch is a row error and must not update the DB.

### 7.6 Affiliate URL

Accept only HTTPS Shopee Affiliate short-link hosts that the existing Shopee Direct workflow recognizes, primarily:

```text
s.shopee.vn
```

Do not resolve the short link during CSV parsing or import.

## 8. Multi-file behavior

One upload may contain multiple CSV files.

All rows are normalized into one preview batch.

Deduplication key inside the upload:

```text
(shop_id, item_id)
```

If the same product appears in multiple uploaded files:

- prefer the **last valid occurrence** in upload order;
- count earlier occurrences as `DUPLICATE_IN_UPLOAD`;
- show source filename/row in preview;
- only one DB mutation is performed for that canonical product.

This rule is deterministic and easy for the operator to understand.

## 9. Preview-before-import contract

Uploading files must not immediately mutate Product rows.

Flow:

```text
POST /sanpham/shopee-import/preview
  → parse files
  → normalize rows
  → compare against DB read-only
  → render preview
```

Preview summary:

```text
Files: 5
Rows read: 500
Valid unique: 472
New: 320
Will update: 140
Unchanged: 12
Duplicates in upload: 18
Errors: 10
```

Preview table should show at least:

```text
status
item_id
product name
price
sold count
shop
commission %
commission amount
product URL
affiliate URL (truncated UI, full copy value)
source file + row
error message when applicable
```

The operator then explicitly chooses **Import**.

## 10. Import confirmation and tamper resistance

The confirmation request must not trust arbitrary hidden form rows posted back from the browser.

Recommended design:

- preview creates a short-lived server-side import batch record or signed payload reference containing normalized rows;
- confirmation refers to that batch identifier;
- import reuses the normalized server-side data;
- batch expires after a conservative TTL;
- batch is one-time consumable after successful import.

To avoid a new permanent staging subsystem, the initial implementation may use an in-memory short-TTL store matching the existing helper-pairing pattern, provided:

- restart losing a pending preview is acceptable;
- no secrets are stored;
- raw CSV bytes are not retained;
- normalized rows only are retained until import/expiry.

If process persistence is required later, promote this to a dedicated staging table in a separate change.

## 11. Product upsert semantics

For each unique valid row:

### Existing canonical Shopee Product

Update only fields supplied by the CSV:

```text
name
current_price
shop_name
units_sold
commission_rate_percent
commission_amount
commission_value
product_url
affiliate_url
affiliate_short_url
affiliate_link_status
affiliate_link_error
affiliate_link_created_at
last_seen_at
last_synced_at
updated_at
```

Preserve richer fields not present in the CSV:

```text
image URLs/local image
rating
review_count
category
original_price
facts/content metadata
post history
```

### New canonical Shopee Product

Insert through the existing Product normalization/upsert path where practical.

If the existing Product schema requires values the CSV cannot provide, use existing safe defaults only where ACP already defines them. Do not fabricate business facts.

If a required field cannot be safely populated, mark the row as an import error rather than inventing data.

## 12. Affiliate semantics

The CSV's `Link ưu đãi` is provider-created and authoritative for this import.

Rules:

- store it unchanged;
- do not append or rewrite `sub_id`;
- do not call the Phase 1 generator;
- do not resolve it during import;
- mark link state `READY` when syntactically valid;
- clear prior affiliate-link error for that Product;
- update affiliate link timestamp.

If a later CSV contains a different valid Shopee Affiliate URL for the same item, the latest confirmed import replaces the stored affiliate URL.

## 13. Price history interaction

CSV import is an operator-confirmed price observation.

Reuse the existing Shopee price-history semantics:

- first observation creates history;
- unchanged price does not create a duplicate history point;
- changed price creates one new observation;
- source should identify CSV import, either by extending the allowed source enum deliberately or by mapping to the existing explicit source convention without changing unrelated feed behavior.

The exact source label must be chosen once in implementation and tested; recommended label: `affiliate_csv`.

```text

```

Page structure:

```text

[ Chọn file CSV ... ]  (multiple)
```

No CTA on this page creates a post or publishes.

## 15. File and request safety

- `.csv` only in the initial implementation.
- Enforce per-file and total request size limits.
- Enforce maximum row count per preview batch to prevent accidental memory abuse.
- Reject binary/invalid CSV content cleanly.
- Never execute spreadsheet formulas/macros; CSV is treated as text only.
- Do not persist uploaded raw files.
- Do not log full CSV body.
- Do not log credentials/secrets.
- Existing dashboard authentication and CSRF protection apply to preview/import actions.

Recommended initial limits:

```text
max files: 20
max file size: 5 MiB each
max total parsed rows: 20,000
```

These are operational limits, not Shopee platform limits.

## 16. Error handling

Batch-level errors:

- no file selected;
- unsupported extension;
- request/file too large;
- missing required columns;
- invalid encoding/corrupt CSV;
- total row cap exceeded.

Row-level errors:

- missing item ID/name/price/product URL/affiliate URL;
- invalid price;
- invalid commission values;
- invalid product URL;
- item ID mismatch;
- invalid affiliate host.

A bad row must not block valid rows from being previewed/imported.

Import must return a deterministic summary and retain row-level failures for display.

## 17. Audit and observability

Record aggregate import events without storing full CSV content or full affiliate URL in audit detail.

Suggested events:

```text
shopee_csv_preview
shopee_csv_import_completed
```

Safe detail example:

```json
{
  "files": 5,
  "rows": 500,
  "new": 320,
  "updated": 140,
  "unchanged": 12,
  "duplicate": 18,
  "error": 10
}
```

Do not place raw rows or affiliate URLs into `audit_log.detail`.

## 18. Testing

### Parser unit tests

Use synthetic fixtures derived from the verified CSV shape.

Cover:

- exact nine-column contract;
- UTF-8 BOM;
- quoted product names with commas;
- `53,9k`, `1,2tr`, `100,0tr`;
- `42,5%`;
- `₫4.000.000`;
- `300k+` sold-count-like value;
- canonical URL identity;
- item-ID mismatch;
- invalid affiliate host;
- missing required columns;
- duplicate rows across files.

### DB tests

Cover:

- new Product insert;
- existing Product update;
- same product imported twice remains one Product;
- richer existing metadata is preserved;
- latest official affiliate URL replaces older one;
- affiliate state becomes READY;
- unchanged price does not duplicate history;
- changed price creates one history row;
- malformed rows do not mutate DB.

### Web tests

Cover:

- authenticated page;
- CSRF protection;
- multi-file preview;
- preview does not mutate DB;
- confirmation imports exactly previewed normalized rows;
- replayed/expired preview batch is rejected;
- request size/row limits;
- results summary rendering.

### Regression

At minimum run relevant Shopee tests plus:

```bash
ACP_ADAPTER=mock ACP_SOURCE=mock python -m acp.tests.test_pipeline
ACP_ADAPTER=mock ACP_SOURCE=mock python -m acp.tests.test_pilot
python tests/test_manage.py
./manage.sh test
```

No test may publish a real Threads post.

## 19. Rollout

1. Implement parser and normalization with no web/DB dependency.
2. Implement preview-batch lifecycle.
3. Implement idempotent Product upsert and price-history integration.
4. Add authenticated/CSRF-protected multi-file web flow.
5. Add docs and focused tests.
6. Run full release verification in mock mode.
7. Controlled pilot using a copy of a real Shopee CSV against a non-production/test DB first.
8. Only after verification, merge to `main`.

## 20. Definition of done

- Multiple official Shopee Affiliate CSVs can be uploaded in one action.
- Real Vietnamese price/commission/sold-count formats parse correctly.
- Preview is read-only.
- Import requires explicit operator confirmation.
- Duplicate products do not create duplicate Product rows.
- Existing richer Product metadata survives CSV updates.
- Official `Link ưu đãi` is stored unchanged and marked READY.
- Import does not call the bulk link generator.
- Import does not create posts/jobs or publish.
- Row-level errors are isolated and visible.
- Relevant focused/regression/release tests pass with exact command output.
- No raw CSV, runtime DB or secrets are committed.

## 21. Later phase: automatic Downloads ingestion

Not part of this implementation.

A later design may add a local operator-side watcher:

```text
~/Downloads
  → detect newly completed Shopee bulk-link CSV
  → checksum/dedupe file
  → submit to ACP importer
  → notify operator of preview/import result
```

That phase must remain opt-in and local, and must reuse the importer implemented here rather than creating a second ingestion path.
